WHAT CHANGED

  BRAND
    New horizontal nav lockup replaces the old 350x375 stacked mark,
    which was square and rendered its wordmark ~5px tall in a 45px
    nav bar. Built from Logos/PNG/SVG/Asset 92.svg by _build_brand.py.
    Full favicon/app-icon set generated from the same master.
    favicon.ico / favicon.png / favicon.webp / webclip.png were
    replaced IN PLACE, so every page picks the new icons up without
    a markup change.

  MOBILE UI (reported from an iPhone)
    - hero buttons had mismatched padding (13px 22px vs 16px 32px)
      in a nowrap row, so each label broke over three lines at a
      different width. Now one column, one shared 320x54 box.
    - .highlight paints gradient text via background-clip:text AND
      filter: drop-shadow() on the same element. iOS Safari drops the
      clipped paint when a filter is present, so accent words in
      headings rendered invisible. Touch devices now get a solid
      brand fill with a text-shadow glow; desktop keeps the gradient.
    - .section had 100px vertical padding on phones (most of a screen
      of nothing, which read as a missing section). Now 56px.
    - interior heroes stretched to 100vh for ~355px of content.
      Now content-sized; live-360 heroes keep viewport presence.
    - live tour viewport was a 16:9 letterbox ~220px tall on a phone.
      Now 3/4 portrait, min 440px.
    - Arboeden case study showed a static JPEG where the tour should
      be. Now embeds the real tour via the new js/live-tour.js.

  HERO 360 REEL
    Every service and industry page showed the same single panorama.
    js/polish.js now runs the hero as a Pannellum multi-scene tour,
    cross-fading five high-res client panoramas every 7s with a
    caption naming the location. Pauses while dragged, respects
    prefers-reduced-motion. Per-page override: data-panorama-set.

  AR EXPERIENCE (AR Version/)
    Root cause of the dead AR button: the page loaded 8th Wall's
    engine from a generic npm CDN with no app key, so XR8.run()
    failed on every device with "No valid session manager to handle
    this session" - and startEighthWallARSession() returned true
    immediately after calling run(), so the caller's fallback never
    fired. The overlay opened, stuck on "STARTING AR CAMERA", and
    never requested a camera.
      - engine now only loads when a key is set in
        window.YOUSEE360_AR_CONFIG.eighthWallAppKey (index.html)
      - 8th Wall start is confirmed via onStart / onException / an
        8s timeout, and hands the canvas back on failure
      - the launcher is a real cascade: WebXR immersive-ar (which was
        implemented but never called) -> 8th Wall if keyed ->
        getUserMedia camera preview -> recovery UI
      - HUD rebuilt around a data-ar-state machine: one primary
        action at a time, camera permission priming sheet before the
        browser prompt, scene picker moved into a bottom sheet,
        safe-area insets, haptics, Escape to close.
      - AR page assets now carry ?v= like the rest of the site; they
        previously had none, so returning visitors kept stale JS/CSS.

  ALSO

    - es/industrias/fotografia-propiedades.html linked to

    - asset token bumped 20260904a -> 20260908a on all 98 pages, so

    - _rebuild_bundles.py now retries writes and deletes old bundles

      stylesheet mid-run.
